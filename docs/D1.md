# D1 (Cloudflare database)

Binding: `DB` (`wrangler.jsonc` → `d1_databases`, migrations in `drizzle/`).
Code access: `getDb(c.env.DB)` (`src/db/index.ts`) — one Drizzle client per request.

## First-time setup

```bash
cp .dev.vars.example .dev.vars   # fill JWT_SECRET + CLOUDINARY_API_SECRET
bun install
# create the database (needs `bunx wrangler login` once):
bunx wrangler d1 create mike
# → paste the returned database_id into wrangler.jsonc (replacing the zeros)
bun run db:apply:local            # creates all tables locally
bun run dev                       # http://localhost:8787
```

`wrangler dev` uses a **local** D1 automatically — no remote needed to develop.
Remote (when ready):

```bash
bun run db:apply:remote
bunx wrangler secret put JWT_SECRET
bunx wrangler secret put CLOUDINARY_API_SECRET
bun run deploy
```

## Useful commands

```bash
bunx wrangler d1 list
bunx wrangler d1 execute mike --local  --command "SELECT count(*) FROM products;"
bunx wrangler d1 execute mike --remote --command "UPDATE users SET role='admin' WHERE email='you@example.com';"
bunx wrangler d1 migrations list mike --local
```

## Seed demo data (local)

```bash
bunx wrangler d1 execute mike --local --file ./scripts/seed.sql
```

## Notes / limits

- D1 is SQLite: no `ILOVE`/`ILIKE` (search uses `LIKE`, ASCII case-insensitive), no enums (checked in zod), no multi-statement transactions — checkout uses `db.batch()` instead.
- Free tier: 5GB storage, 5M reads/day — plenty for MVP; add indexes (already on `products.category/active`, `orders.user/status`) before scaling search.
- Backups: `bunx wrangler d1 export mike --remote --output backup.sql`.
